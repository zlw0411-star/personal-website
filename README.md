# 关于我 · 本地个人网站

一个简洁的中文个人网站，包含公开文章、个人介绍和受管理员认证保护的内容管理页。开发时内容存放在本地 D1/R2 模拟器中；Sites 公网环境可使用云端 D1/R2。浏览器 `localStorage` 不保存网站内容。

## 模板来源与二创

前台 Hero、About、内容分区、经历时间线，以及页头导航和页脚结构适配自 [React Resume Template](https://github.com/tbakerx/react-resume-template)，固定上游版本为 `49ce16c0dd1b382edc1ec2cef6120345776d19b9`。首页采用米白背景、蓝绿色点缀的图文布局，按动态 Profile 展示简介与一次真实头像，并以时间线呈现经历；页面继续使用本站动态 Profile/Entry 数据，没有复用模板作者的示例资料或图片。原 SVG 场景文件保留在仓库中，但首页不再引用。许可范围和来源文件见 [第三方声明](THIRD_PARTY_NOTICES.md) 与 [MIT 许可文本](vendor/react-resume-template/LICENSE)。

## 本地运行

需要 Node.js 22.13 或更新版本。首次准备依赖和本地数据库：

```sh
npm ci
npm run setup:local
```

启动开发服务器：

```sh
npm run dev
```

打开 <http://127.0.0.1:5173>。开发服务器绑定到 `127.0.0.1:5173`；管理页仅在本地开发服务器开放，访客只能浏览，修改内容还需管理员登录。生产构建不开放管理 API。停止服务器按 `Ctrl+C`。

Windows 用户也可以双击项目根目录的 `启动网站.cmd`。它会在缺少依赖时安装依赖、准备本地数据库，然后启动开发服务器；终端会显示首页和管理页地址。此启动方式不会自动打开浏览器。

`npm start` 使用生产构建进行本地预览，默认只能浏览网站内容，管理 API 保持关闭。只有显式配置下文所列的托管环境变量后，生产管理 API 才会开放。编辑内容请使用 `npm run dev` 或 `启动网站.cmd`。

## Sites 公网环境

当前状态：Sites 项目已注册但尚未发布；公网发布与相关验收按用户要求暂停，网站本地数据尚未迁移。

部署到 Sites 时，网站通过 HTTPS 提供访问，并使用云端 D1/R2 保存网站数据。公开页面只需要公开内容；不要把内容数据库或迁移数据提交到 Git。需要迁移正文时，通过网站管理员 API 导入，迁移数据独立于源码仓库管理。

生产环境默认关闭管理功能。需要启用时，在 Sites 的服务端 runtime 配置 `SITE_ADMIN_ENABLED=true`，并将 `SITE_ORIGIN` 设置为网站的精确 origin（包含协议和域名，不带路径）；浏览器端不读取管理密钥或这些服务端变量。公开页面的“管理内容”入口始终显示，真正的访问控制由服务端 gate 和管理员密码认证执行。

首次在空云端数据库启用管理员认证时，在服务端 secret 中设置 `SITE_INITIAL_SECURITY`，其值为带盐密码哈希记录。该初始化只在 security 表为空时写入；如果表中已有管理员密码，则不会覆盖。请勿把 secret 或哈希记录写入 Git、公开页面或部署说明。设置完成后，可通过 `/admin` 登录并使用管理员 API 导入正文。

尚未部署或迁移时，不应将本地预览描述为公网服务；启用公网管理还需在 Sites runtime 完成上述配置，并使用管理员 API 独立迁移内容。

## 导航与内容填写

首页现在合并了个人介绍；在管理页编辑的个人资料会显示在首页。原 `/about` 地址会转到首页。导航中的「学习」栏目现显示为「经历」，地址为 `/experience`；原 `/learning` 地址会转到「经历」。已有学习文章和原「项目」文章会显示在「经历」栏目，项目链接字段仍会保留。

求学、实习和工作内容请在管理页新增文章并选择「经历」分类。标题可填写时间和学校或单位，正文记录具体内容；请按真实经历填写。

个人资料可添加多种联系方式（邮箱、电话、链接或文字说明），旧邮箱和链接仍会继续显示。管理页可从选中的经历与生活记录整理个人介绍和经历概览：经历概览只使用经历，个人介绍按经历约 3:1 生活的篇幅比例取材。预览会显示实际进入结果的来源数量和因篇幅或缺少可摘录文字而省略的条目；来源供你检查。结果是从文章摘要或正文摘出的草稿，不会自动写回个人资料，也不会补造未记录的信息。富文本中的图片、代码和链接地址不参与摘录。

后台内容列表和生成来源选择器只读取列表需要的字段，不加载富文本正文；点开单篇文章后才读取正文用于编辑。列表仍展示分类、标题、摘要、状态、可见范围和更新时间。

本地开发服务器绑定到本机；本地管理 API 要求独立的管理员登录会话。首次启用管理员登录时，迁移会把当时的生活密码哈希复制为管理员密码，不会读取或保存明文。之后修改生活密码不会改变管理员密码；两类会话互相独立。不要将开发服务器端口转发或暴露到局域网或互联网。

「生活」栏目受独立密码保护。访客需在栏目页解锁；解锁会创建最长 12 小时的浏览器会话。管理员可在本地管理页 `/admin/privacy` 设置或更改生活密码，更改后会撤销已有生活会话，但不会修改管理员密码。

## 验证本地 API

Profile 联系方式与摘录逻辑可在不启动网站、不写入数据库的情况下检查：

```sh
node --experimental-strip-types scripts/verify-profile-generation.mjs
```

Profile 的 D1 读写与重启持久化可用独立临时数据库验证；脚本只在 `.sites-runtime/profile-storage-<随机ID>/` 创建并删除自己的验收数据，不访问网站正在使用的 D1/R2：

```sh
node scripts/verify-profile-storage.mjs
```

服务器运行时执行完整验证。脚本只清理它自己生成的文章和图片；它会临时修改个人资料和头像，并在结束时恢复原值。验证期间请暂停编辑网站内容，避免恢复操作覆盖你的同时修改：

```sh
node scripts/verify-local.mjs
```

也可以分两次运行验证重启后的持久化：先准备脚本自己的私密文章和图片，重启开发服务器，再检查并清理：

```sh
node scripts/verify-local.mjs --prepare-persistence
# 重启开发服务器
node scripts/verify-local.mjs --check-persistence
```

本地验收脚本通过标准输入读取管理员密码，不从文件、环境变量或命令行参数读取。例如 PowerShell 可用 `$password | node scripts/verify-admin.mjs`，不要把真实密码写入脚本或日志。`scripts/verify-life.mjs` 默认把 stdin 密码同时用于管理员和生活栏目；若两者不同，可通过 stdin 传入 JSON `{"adminPassword":"…","lifePassword":"…"}`。`verify-admin.mjs` 和 `verify-life.mjs` 只创建并清理带随机标识的测试文章和图片，不修改个人资料或密码；不要在运行时并行编辑这些测试内容。`verify-local.mjs` 会临时修改个人资料和头像并恢复原值，相关说明见上方。

## 备份与恢复

开发服务器停止后，复制整个 `.wrangler/state/` 目录即可备份本地 D1 数据和 R2 图片。恢复时先停止服务器，再将备份内容放回 `.wrangler/state/`，然后重新运行 `npm run dev`。不要在服务器运行时复制状态目录。`.sites-runtime/` 主要保存本地工具状态，也可能包含手动导出的数据库备份；网站正常运行数据以 `.wrangler/state/` 为准。本次 life 保护调整前的数据库备份为 `.sites-runtime/before-life-protection.sql`；本次 admin 登录调整前的数据库备份为 `.sites-runtime/before-admin-auth.sql`；本次个人资料工具调整前的数据库备份为 `.sites-runtime/before-profile-tools.sql`。三者都是 D1 SQL 备份，不包含 R2 图片。若在没有 `life_security` 数据的全新数据库上应用管理员迁移，管理员密码不会被初始化；请从已有备份恢复数据，不提供公开的密码初始化接口。`.vinext/` 保存开发服务器状态；清理本地目录前请保留需要的备份。
